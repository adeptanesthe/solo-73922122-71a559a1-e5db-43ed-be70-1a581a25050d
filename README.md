# 期货跨期保证金演练台（Flask）

用**合成数据**演练同一品种近月 / 远月合约的跨期保证金：交易员设置期初净持仓与
账户资金后，可在网页上挂单、报成交、撤余单，并实时看到“所有挂单任意成交组合下
的最高保证金”及一组达到该值的成交手数。

## 一、功能与业务规则

| 主题 | 规则 |
| --- | --- |
| 期初设置 | 账户资金（元，非负整数）、近月/远月期初净持仓（手，带方向，正多负空），可随时重置演练 |
| 挂单数量 | 活动挂单最多 **12 笔**，每笔最多 **10 手**、最少 1 手 |
| 单腿单 | 指定近月或远月、买/卖，可独立成交任意 1..剩余 手 |
| 跨期单 | 一买一卖：买单 = 近月 `+1` / 远月 `-1`，卖单相反；两腿**等量同步成交** |
| 保证金 | `100 × (|近月净持仓| + |远月净持仓|) − 80 × 反向配对数`，配对数 = 两月方向相反时的 `min(|近月|, |远月|)` |
| 上限试算 | 考虑每张活动挂单从 **0 手到剩余手数**的全部成交组合，取最高保证金，并给出一组成交手数 |
| 挂单校验 | 试挂后若上限 > 账户资金则**拒单（HTTP 422）**，响应携带完整试算结果；原持仓与挂单不变 |
| 登记成交 | 同步更新两月净持仓与单据已成交/剩余手数，全部成交后状态置为“全部成交”，并重算上限 |
| 撤单 | 只撤未成交部分（已成交部分保留），状态置为“已撤销”，并重算上限 |
| 纯试算接口 | `POST /api/orders/trial` 只返回试算结果，不写入任何状态 |

## 二、为什么只需枚举“每张单 0 手 / 全部成交”（2^N 个顶点）

记两月净持仓为 `(x, y)`，保证金函数为

```
M(x, y) = 100|x| + 100|y| − 80·pairs(x, y)
pairs(x, y) = min(|x|, |y|)  当 xy < 0，否则为 0
```

- `100|x| + 100|y|` 是凸函数；
- 在任一象限内 `pairs` 是线性函数；跨越坐标轴 / 对冲区边界时，`−80·pairs`
  的斜率单调不减（例如固定 `y < 0`、`x` 从负到正：先斜率 `−20`（对冲区），
  过 `x=0` 后斜率 `+100`），因此 `−80·pairs` 也是凸的；
- 故 `M(x, y)` 是凸的逐段线性函数。

每张挂单成交 `q_i` 手可在区间 `[0, remaining_i]` 内任意整数取值，最终持仓是
`q_i` 的线性函数，复合后的保证金在“成交手数盒子”上仍为凸函数。**凸函数在盒子
（含整数格点）上的最大值必在顶点取得**，即每张单要么不成交、要么全部成交。
因此枚举 `2^N`（`N ≤ 12`，最多 4096）个顶点即可严格求出题目要求的最大值；
测试中的 `worst_case_bruteforce` 会对 300 组随机小场景做逐手全枚举交叉验证。

## 三、运行方式

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

容器以 gunicorn 单 worker + 8 线程运行（演练状态保存在进程内存中，由锁保护，
故必须保持单 worker）。停止：`docker compose down`。

### 本地直接运行

```bash
pip install -r requirements.txt
python wsgi.py            # http://localhost:8000
```

### 自测

```bash
python -m pytest tests/ -q
```

## 四、HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 演练页面 |
| GET | `/api/state` | 当前完整状态（资金、持仓、当前/最高保证金、上限成交组合、单据、日志） |
| POST | `/api/setup` | 重置演练：`{cash, near_position, far_position}` |
| POST | `/api/orders` | 挂单：`{kind: single|spread, leg: near|far（单腿必填）, direction: buy|sell, lots}` |
| POST | `/api/orders/trial` | 纯试算，不入账，返回同结构的试算结果 |
| POST | `/api/orders/<id>/fill` | 登记成交：`{lots}`（1..剩余手数） |
| POST | `/api/orders/<id>/cancel` | 撤销未成交部分 |

拒单响应示例（HTTP 422）：

```json
{
  "error": "试挂超出资金，拒单（原持仓和挂单保持不变）",
  "trial": {
    "accepted": false,
    "cash": 600,
    "projected_max_margin": 900,
    "shortfall": 300,
    "fills": [{"order_id": "...", "fill_lots": 10, "is_candidate": true, "...": "..."}]
  }
}
```

## 五、目录结构

```
app/
  margin.py            # 保证金公式、配对、顶点枚举/暴力枚举（纯函数）
  server.py            # Flask 路由、内存状态与业务校验（线程锁）
  templates/index.html # 单页界面
  static/app.js        # 前端交互（挂单/成交/撤单/试算弹窗/渲染）
  static/styles.css
tests/                 # pytest：引擎公式、300 组随机交叉验证、API 全流程
Dockerfile, docker-compose.yml, wsgi.py, requirements.txt
```

## 六、已知限制

- 状态为单进程内存存储，重启容器即恢复默认演示场景；未做持久化与多实例部署。
- 仅模拟同品种两个合约月，不处理手续费、涨跌停、部分成交回报推送等真实交易细节。
